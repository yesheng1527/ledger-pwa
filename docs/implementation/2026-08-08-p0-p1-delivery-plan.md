- 数据：IndexedDB + outbox + Supabase 同步骨架已存在；交易领域层已支持 create/update/delete/restore、transfer、adjustment，UI 仅暴露其中一部分。

## 发布门禁

1. 旧数据迁移必须幂等：使用版本化交易文本信封在现有后端 `note` 列中无损保存名称与备注；旧纯文本 `note` 作为备注保留，显示名称回退到类目，不覆盖用户内容。迁移前后需有固定快照测试。
2. 转账统计必须恒为中性：转出、转入更新双方余额，但不进入收入、支出、预算消耗、类目占比或月度收支对比。
3. 账户生命周期必须保留流水审计链：默认停用；永久删除只允许无关联流水的账户。有关联流水时必须阻止并提示“停用或先迁移流水”，不得级联删除流水。
4. 游客模式使用独立数据库名、固定本地 ledger/user id，禁用 Supabase client、AuthService、LedgerApi 和正式 outbox；退出游客模式后正式账号不得看到游客数据。
5. 离线操作以唯一 `operationId` 入 outbox；本地重复保存与联网重试必须幂等，服务端冲突进入 conflict store，不得重复记账。
6. 最终发布前保留源码 tag/分支或明确提交号作为恢复点；只允许在全矩阵通过后触发 Pages 部署。

## 横向产品与视觉验收

- 390×844、320×568、844×390、1440×900 无关键内容不可达；横屏允许纵向滚动；桌面合理居中或双栏。
- 所有关键触控区最小约 44×44px；上传/恢复使用真实 button + 隐藏 input；键盘焦点可见。
- 记账弹层遮罩与内容同一动画帧开始，200–320ms 完成；捕获中间帧确认无“只有遮罩”。
- 空首页/流水/统计显示“记第一笔”引导；游客首页展示可理解的示例价值。
- 状态变化使用 `role=status`/`aria-live`，错误使用 `role=alert` 并关联到字段。
