## 1. 目标

把现有可运行账本收敛为与视觉基准一致的五页移动端产品，并补齐统计、记账、账户、分类、预算、提醒、备份恢复和偏好设置等完整功能。

本次工作必须同时满足：

1. 首页、流水、记账、统计、我的五页使用同一套海边手绘视觉系统。
2. 所有金额、统计和管理状态来自真实本地账本与云端同步数据，不使用生产演示数据。
3. 保留已完成的离线优先、原子记账、云同步、编辑、软删除和八秒撤销能力。
4. 不删除现有本地或云端账目，不用视觉重构替代数据安全门禁。
5. 在 320×568、390×844、430×932 三种视口上保持可用、可访问且无文档级横向溢出。

## 2. 已确认的交付方式

采用三个可独立验收的纵向阶段，不进行一次性“大爆炸”改造。

### 阶段一：五页视觉骨架、完整记账和真实统计

- 重建统一设计令牌、页面外壳、底部导航和独立视觉资产。
- 首页、流水、详情、编辑和撤销行为保持可用，并按视觉基准重新排版。
- 中央记账按钮打开全屏记账页，完成支出、收入、转账、退款和余额校准的新增流程。
- 统计页完成月、年、自定义区间的真实指标和可访问图表。
- “我的”页先完成真实同步/账号状态和完整功能入口；阶段二、三入口在各自功能完成前不进入正式基线。

### 阶段二：账本管理和提醒

- 账户管理。
- 分类管理。
- 总预算和分类预算。
- 固定账单与记账提醒。
- 本机识别的小票/付款截图辅助记账草稿。

### 阶段三：数据可携带性、偏好和最终验收

- JSON 完整备份。
- 带检查预览、影响摘要和二次确认的 JSON 恢复。
- CSV 流水导出。
- 同步状态、待同步数量和冲突入口。
- 海风主题、减少动效等偏好。
- 账号安全信息和退出登录。
- 全应用视觉、功能、离线、恢复和云同步验收。

## 3. 唯一视觉方向

视觉基准图是唯一方向，不再生成替代风格。

### 3.1 视觉语言

- 米白纸张纹理作为应用底色。
- 暖色细边框、轻柔阴影和中等大圆角卡片。
- 珊瑚红用于主按钮、当前导航和选中状态。
- 红色表示支出，绿色表示收入，橙色表示结余或预算提醒，海蓝用于插画氛围。
- 图标采用统一描边、粉彩填色的手绘风格；禁止 emoji、系统占位图标、CSS 拼图和文字字符假图标。
- 插画、贝壳品牌标识、分类图标和管理图标必须是独立 SVG 或 2x/3x 位图资源，不得把整张参考图作为页面背景或裁切成界面。

### 3.2 基础令牌

实施时以参考图实测为准，初始令牌范围如下：

- 页面底色：`#fff9ef` 附加低对比度纸张纹理。
- 主要文字：`#34312e`。
- 次要文字：`#756f68`。
- 珊瑚红：`#f46d58`。
- 海蓝：`#8bcfe8`。
- 结余橙：`#e8892e`。
- 支出红：`#e85043`。
- 收入绿：`#2e9b68`。
- 卡片：约 88%–96% 不透明的暖白。
- 控件圆角：10–14px；卡片圆角：14–20px；胶囊和中央记账按钮使用全圆角。
- 点击目标最小 44×44px。
- 字体使用离线安全的中文系统栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。

### 3.3 移动端结构

- 正式页面不复制参考图中的手机状态栏、信号、电量或设备边框。
- 移除现有每页重复出现的全局“海风小账本”顶部横栏。
- 页面使用各自的紧凑标题或插画头图。
- 底部固定五栏：首页、流水、中央凸起记账按钮、统计、我的。
- 中央记账是操作，不是第五个可保留滚动状态的普通面板；打开后进入全屏记账层。
- 首页、流水、统计、我的四个普通面板保持挂载，以保留筛选和滚动位置。

## 4. 五页信息架构

### 4.1 首页

自上而下：

1. 海边问候插画、问候语和提醒入口。
2. 月份选择与财务总览：总资产为最大数字，同时显示本月结余、本月收入和本月支出。
3. 本月预算：总额、已用、剩余、比例和接近超支提示。
4. 快速记账：餐饮、交通、购物、娱乐和更多。
5. 最近交易：默认三条，提供进入全部流水的入口。
6. 同步状态：正常时使用弱提示；离线、失败、冲突或待同步时明确呈现。

首页所有指标继续遵守既有账务口径：转账、信用卡还款和余额校准不计普通收支，退款冲减原支出。

### 4.2 流水

自上而下：

1. 标题与搜索入口。
2. 月份、账户、日期筛选。
3. 可横向滚动的分类胶囊。
4. 按日期降序分组的紧凑流水。

日期标题显示当日支出和收入合计。每行显示独立分类图标、标题、分类、时间、账户和金额。转账以中性色展示两个账户。点击行进入详情；详情提供同类型编辑、软删除和八秒撤销。

### 4.3 记账

记账是全屏操作层，不显示底部导航：

1. 关闭按钮与支出/收入/转账类型切换；退款和余额校准从“更多类型”进入。
2. 自动聚焦的大金额输入。
3. 两行手绘分类图标。
4. 备注、日期时间和账户。
5. 固定在安全区上方的珊瑚红保存按钮。

约束：

- 所有金额只通过统一人民币解析器转换为整数分。
- 转账的转出和转入账户必须不同，负债账户不能作为转出来源。
- 退款关联原支出并固定使用原账户。
- 余额校准明确选择增加或减少余额。
- 默认账户记住上次选择，默认日期时间为当前本地时间。
- 保存失败保留用户输入并聚焦责任字段，原始异常不直接显示。

### 4.4 统计

结构与视觉基准一致：

1. 月、年、自定义区间。
2. 支出、收入、结余三项摘要。
3. 总预算和分类预算进度。
4. 支出分类占比。
5. 收支趋势。
6. 月度对比。
7. 资产账户与负债账户分布。

图表由领域选择器产生稳定数据，不在组件中重新计算账务口径。每张图提供同等信息的文字摘要；颜色不是唯一信息表达方式。

### 4.5 我的

结构与视觉基准一致：

1. 海边与海鸥插画头图、贝壳标识和个人账本信息。
2. 本月预算卡。
3. 账户管理、分类管理、预算管理、固定账单和记账提醒。
4. 云同步、待同步数量和冲突入口。
5. JSON 备份、JSON 恢复和 CSV 导出。
6. 海风主题、减少动效和其他偏好。
7. 账号安全、关于和退出登录。

二级管理页沿用同一纸张、卡片、图标、边框和导航语言，不另造一套视觉。

## 5. 功能与数据边界

### 5.1 页面依赖

- 页面只依赖 `LedgerViewModel`、领域纯类型/格式化函数和设计系统。
- 页面不得直接访问 Dexie、Supabase、同步引擎或服务层。
- 账务计算、统计选择器、导入校验和 CSV 转换保持可独立测试。

### 5.2 记账与统计

- 新增 `TransactionCreateInput` 判别联合，覆盖五种业务类型。
- 新增记账草稿控制器，负责默认值、上次账户、校验、提交和错误聚焦。
- 新增统计查询模型，接受月、年或自定义区间，返回汇总、分类、趋势、预算和账户分布。
- ViewModel 订阅刷新可以更新展示数据，但不得清空正在编辑的草稿。

### 5.3 管理功能

- 账户、分类、预算和提醒的写入继续使用带 UUID 幂等键的领域操作。
- 被历史流水引用的账户和分类只能停用，不能硬删除。
- 账户明确区分资产与负债；分类明确区分收入与支出。
- 同一月份只允许一个有效总预算，同一月份/分类只允许一个有效分类预算。
- 固定账单只创建提醒；用户确认后才生成真实流水。

### 5.4 本机截图识别

- 识别只在当前设备完成，不上传截图。
- 识别结果只生成可编辑草稿，绝不自动保存流水。
- 用户确认或取消后立即释放图片引用，不进入备份和同步。
- 无法识别时提供普通手动记账路径，不阻塞核心流程。

### 5.5 备份、恢复和导出

- JSON 备份包含当前用户完整本地账本、待同步操作、冲突草稿和版本信息。
- 恢复分为文件校验、预览、二次确认、原子应用和结果回执。
- 恢复失败必须保持恢复前账本不变。
- 重复导入同一恢复包通过恢复回执保持幂等。
- CSV 只导出可读流水字段，不包含认证令牌、同步内部状态或敏感凭据。

## 6. 离线、同步与云端安全

- 不删除现有本地或云端账目。
- 新数据结构只通过可回滚、带版本号的增量迁移加入。
- 所有用户数据继续受 Supabase RLS 保护；浏览器只使用 publishable/anon key。
- 金额始终以整数分持久化。
- 转账、退款和余额校准保持原子写入。
- 所有写操作继续带 UUID 幂等键。
- 离线写入先进入本地 outbox；联网后同步。
- 冲突、待同步和失败均使用用户可理解的中文状态，不显示原始服务异常。
- 备份不得包含密码、访问令牌或 service role key。

## 7. 错误、空状态和可访问性

- 每个查询页具有 loading、空状态、安全 error 和 retry。
- 每个写入表单保留失败前输入，并把焦点移动到责任字段。
- 弹层打开时焦点进入、Tab 可循环、Escape 可关闭，关闭后返回来源。
- 活动页面恰好有一个 `main` 地标。
- 所有可点击目标至少 44×44px。
- 所有图标有可访问名称；纯装饰插画使用空替代文本。
- 收支、警告和图表不能只靠颜色区分。
- 支持系统“减少动态效果”；关闭非必要转场但不隐藏状态变化。

## 8. 测试与验收

### 8.1 测试顺序

每个功能先观察针对需求的失败测试，再做最小实现。至少覆盖：

- 领域金额、统计、预算、导入和导出纯函数。
- ViewModel 查询、创建、管理、离线写入和冲突映射。
- 本地仓库原子性、软删除、恢复回执和用户隔离。
- Supabase RLS、RPC 原子性和幂等。
- 页面键盘、焦点、错误、空状态和 44px 规则。

### 8.2 浏览器验收

在 320×568、390×844、430×932 验证：

- 五页导航和四个常驻面板状态保持。
- 首页指标、预算、快捷入口和最近交易。
- 流水组合筛选、详情、编辑、删除和撤销。
- 五种记账类型的新增和错误恢复。
- 统计区间、摘要、图表文本和账户分布。
- 账户、分类、预算和提醒的新增、编辑、停用。
- JSON 备份/恢复回环、CSV 导出。
- 离线新增、恢复联网同步和冲突提示。
- 安全区、无横向溢出、焦点恢复和减少动效。

### 8.3 视觉验收

- 不使用整张设计稿作为页面背景。
- 每个阶段生成隔离的候选截图，不能绕过官方视觉测试。
- 把同一尺寸、同一状态的参考图和实际截图放在一起比较。
- 修复明显的布局、留白、字号、边框、圆角、颜色、插画比例、裁切和遮挡问题。
- 设计 QA 报告必须以 `final result: passed` 结束。
- 用户明确批准候选图后，才能更新官方视觉基线。

## 9. 阶段完成门槛

每个阶段必须同时满足：

1. 计划内单元、集成和浏览器测试通过。
2. 类型检查和生产构建通过。
3. 生产包不包含测试夹具、临时图片或秘密值。
4. 独立代码审查无 Critical/Important 未解决项。
5. 候选视觉经过用户明确确认。
6. 本阶段验证报告记录代码 SHA、命令结果、截图路径、迁移版本和剩余问题。

## 10. 非目标

- 不增加公开注册或多用户共享产品范围。
- 不购买域名、付费服务或云端 OCR。
- 不自动读取微信、支付宝或银行流水。
- 不把小票或付款截图上传、保存或加入同步。
- 不为匹配参考图而重写正确的账务规则。
- 不在用户批准前更新官方视觉基线或部署生产。
