# 海风小账本 UI 基础、登录门与五栏导航设计

- 日期：2026-07-22
- 状态：用户已确认
- 上游规格：`2026-07-18-auth-sync-design.md`
- 视觉基准：用户交接文档中内嵌的五屏原始设计稿

## 1. 目标

在已完成的认证、个人账本初始化和离线同步基础上，建立可继续扩展的正式 UI 骨架。本阶段交付可使用的登录与密码恢复流程、固定五栏导航、中央记账入口占位层，以及统一的视觉和无障碍基础。

本阶段结束时，未登录用户能够完成登录、申请密码重置和设置新密码；已登录用户能够进入具有正式海边手绘风格的五栏应用框架。五个业务页面只提供正式空状态，不提前实现首页指标、流水列表、完整记账、统计图表或设置管理。

## 2. 范围

### 2.1 本阶段包含

- 设计令牌、全局样式和少量通用组件。
- 贝壳标识、登录海边插画和五个独立导航 SVG。
- `AuthGate` 与登录、忘记密码、设置新密码三种认证状态。
- GitHub Pages `/ledger-pwa/` 子路径下的密码重置回调。
- 首页、流水、中央记账、统计、我的五栏框架。
- 中央记账占位层及关闭后返回原标签的行为。
- 320、390、430 CSS 像素宽度下的布局、触控和安全区验收。
- 登录页与应用框架的稳定浏览器截图基线。

### 2.2 本阶段不包含

- 首页财务卡片和真实账本查询。
- 流水搜索、筛选、编辑、删除和撤销。
- 正式记账表单和业务保存。
- 统计图表及 Recharts 依赖。
- 账户、分类、预算、提醒、冲突和备份管理。
- OCR、Web Push、Service Worker 离线外壳和正式上线切换。
- 公开注册入口。

## 3. 架构

应用保持单一依赖方向：页面只依赖应用运行时和设计系统，不直接访问 Supabase、Dexie 或同步引擎。

```text
AppProviders
  ├─ 会话、初始化与同步状态
  ├─ 登录/重置密码命令
  └─ AuthGate
       ├─ BrandedLoadingState
       ├─ AuthPage
       ├─ InitializationErrorState
       └─ AppShell
            ├─ 五个正式空状态页面
            ├─ EntryPlaceholderSheet
            └─ BottomNavigation
```

`AppProviders` 继续拥有 `AuthService`、`LocalLedgerRepository`、`LedgerApi` 和 `SyncEngine`。它新增面向 UI 的认证命令和密码恢复状态，但不向页面暴露底层客户端。服务边界测试继续禁止 `src/services` 外的 Supabase 运行时导入与调用。

## 4. 组件职责

### 4.1 `AuthGate`

- 初始化中显示品牌加载状态。
- 无会话时显示 `AuthPage`。
- 首次离线或初始化失败时显示明确中文说明和重试入口。
- 有可用会话且本地账本已就绪时显示 `AppShell`。
- Supabase `PASSWORD_RECOVERY` 事件或恢复回调路径优先显示“设置新密码”状态。

### 4.2 `AuthPage`

- 登录状态包含邮箱、密码、登录按钮和“忘记密码”。
- 忘记密码状态只收集邮箱，成功后显示检查邮箱的说明。
- 设置新密码状态包含新密码、确认密码和提交按钮。
- 不显示注册入口；所有者账号继续由既有 Supabase 项目管理。
- 密码不写入 localStorage、sessionStorage、IndexedDB、日志或错误信息。

### 4.3 `AppShell`

- 底部顺序固定为：首页、流水、记账、统计、我的。
- 首页为初始普通标签。
- 四个普通标签切换时保存各自的页面状态和滚动位置接口。
- 中央记账按钮打开独立占位层，不改变上一个普通标签。
- 关闭占位层后返回打开前的普通标签。
- 当前标签通过文字、图标状态和 `aria-current` 同时表达。

### 4.4 设计系统

本阶段建立以下最小组件：

- `Card`：纸张卡片、暖色边框、大圆角和柔和投影。
- `PrimaryButton`：珊瑚红主操作，包含加载和禁用状态。
- `TextField`：标签、说明、错误文本和 44px 触控高度。
- `HandDrawnIcon`：统一图标尺寸、装饰/语义模式和可访问名称。
- `BottomNavigation`：安全区、中央抬高按钮和活动状态。
- `EmptyState`：五个业务页面共用的正式占位结构。

## 5. 认证与导航数据流

### 5.1 登录

1. `AuthPage` 调用运行时 `signIn(email, password)`。
2. 运行时委托 `AuthService`，不复制 access token。
3. Supabase 会话事件进入既有 generation 保护的初始化流程。
4. 在线时先初始化个人账本，再创建同步引擎并同步。
5. 离线且已有本地账本时直接进入应用；首次离线显示既有初始化提示。

### 5.2 密码恢复

1. 用户提交邮箱。
2. 重置邮件回调地址使用 `${location.origin}/ledger-pwa/reset-password`，并由 Vite 基础路径生成，不能写死站点根路径。
3. 回调恢复会话后，`AuthGate` 进入设置新密码状态。
4. 两次密码一致且均不少于 8 个字符后调用 `updatePassword`。
5. 成功后清理恢复状态并进入应用框架。

### 5.3 导航

普通标签由一个类型安全的导航模型定义。记账入口是动作层，不作为会丢失来源位置的普通标签。关闭记账占位层时恢复 `lastRegularTab`。本阶段不引入路由库；密码恢复使用当前路径，应用内部五栏使用本地状态，避免为占位页面增加不必要依赖。

## 6. 视觉与资产

视觉基准保持交接文档中的原始五屏设计稿。本阶段只重绘当前界面所需资产，且每个资产独立存在：

- 贝壳应用标识。
- 登录页海边插画。
- 首页、流水、记账、统计、我的五个导航图标。

不得把整张设计稿或截图裁片作为界面背景，不使用 emoji 或系统通用图标占位。SVG 使用统一暖色描边、圆角端点和粉彩填色，不包含文本、外部图片链接或嵌入式 base64 图片。

锁定的主要设计令牌：

- 纸张：`#FFF9EF`
- 文字：`#34312E`
- 珊瑚红：`#F46D58`
- 海蓝：`#73C5E6`
- 结余橙：`#E8892E`
- 支出红：`#E85043`
- 收入绿：`#2E9B68`

中文字体使用固定版本的 Noto Sans SC Variable，避免不同设备截图依赖系统字体。纸张背景使用项目内低对比纹理；不安装尚未使用的图表依赖。

## 7. 响应式与无障碍

- 支持 320、390 和 430 CSS 像素宽度，无页面横向滚动。
- 固定底部导航和占位层操作避开 `env(safe-area-inset-bottom)`。
- 所有可交互控件至少 44×44 CSS 像素。
- 表单错误使用文字与 `aria-describedby`，颜色不是唯一提示。
- 图标按钮具有中文可访问名称；纯装饰插画使用空替代文本或 `aria-hidden`。
- 焦点在认证状态切换、打开/关闭占位层后移动到正确位置。
- `prefers-reduced-motion: reduce` 时关闭漂浮、弹性和非必要过渡。

## 8. 错误处理

- 邮箱或密码错误：显示“邮箱或密码不正确”。
- 网络不可用：显示“网络连接失败，请稍后重试”。
- 重置邮件发送过于频繁：显示“操作太频繁，请稍后再试”。
- 两次新密码不一致：在确认密码字段显示错误并聚焦该字段。
- 首次离线：保留“首次登录需要联网完成初始化”。
- 其他认证错误：显示固定中文摘要，不渲染 Supabase 原始错误、SQL、响应对象或令牌。
- 重试期间按钮进入忙碌状态，阻止重复提交，但用户可以返回修改邮箱或密码。

## 9. 测试与验收

### 9.1 自动化测试

- `AuthGate` 的加载、未登录、已登录、首次离线和初始化失败分支。
- 登录成功、错误映射、忘记密码成功和失败。
- `/ledger-pwa/reset-password` 回调及更新密码。
- 页面不保存密码或令牌。
- 五栏文字和顺序固定。
- 中央记账入口打开、关闭并返回原普通标签。
- 当前标签语义、44px 触控目标、焦点恢复和减少动态效果。
- 服务边界继续禁止页面直接导入 Supabase 运行时代码。

### 9.2 浏览器验收

- 320×568、390×844、430×932 三种视口无横向滚动和安全区遮挡。
- 登录页和应用框架各生成稳定截图。
- 字体加载完成后再截图，关闭非确定性动画。
- 登录页具有米白纸张、海蓝插画、贝壳标识和珊瑚红主按钮。
- 导航具有五个独立手绘图标，中央记账按钮视觉突出。
- 页面中不存在 emoji、缺字方框或整张设计稿截图。

## 10. 完成标准

- 未登录、密码恢复、已登录三个主流程可用且有中文错误反馈。
- GitHub Pages 子路径下的密码重置地址正确。
- 已登录用户看到稳定的五栏框架，记账占位层返回逻辑正确。
- 五个业务页仍是明确占位，不包含伪造财务数据。
- 单元测试、类型检查、生产构建和本阶段浏览器验收全部通过。
- 页面和组件没有直接访问 Supabase 或 Dexie。
